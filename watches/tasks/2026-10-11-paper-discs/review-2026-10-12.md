## Findings

### 1. P2 — The capability fallback exposes the hidden mechanism

**Locations:** `webgl/renderer.ts:669`, `webgl/renderer.ts:1002`, `webgl/renderer.ts:1346`, and `watch/generate.ts:2957`.

Without `EXT_color_buffer_float`, the renderer omits the slope texture. Every line then uses the ordinary depth tolerance:

$$
HIDDEN\_LINE\_TOLERANCE = 0.25
$$

The wheel clearance is:

$$
STACK\_GAP = 2\,HOLDOUT\_TOLERANCE = 0.0625
$$

Thus, the fallback tolerance exceeds the clearance by a factor of four. Lines directly below a holdout remain visible.

I verified this with the current renderer in all three engines. A synthetic line beneath a holdout produced zero dark pixels with slopes. Without slopes, it produced 492 dark pixels at each tested tilt: 0°, 20°, 45°, 60°, and 75°.

I also drew current watch states at 1960 × 1104. The table counts visible darker pixels added by the fallback. A visible change exceeds 32 in at least one colour channel.

| Watch state         | Chromium | Firefox | WebKit |
| ------------------- | -------: | ------: | -----: |
| Cover               |    4,150 |   4,150 |  4,150 |
| Mainspring, click 3 |    8,064 |   8,058 |  8,058 |
| Hour Hand, click 3  |   17,526 |  17,525 | 17,525 |

There were no visible lighter changes. The synthetic draws produced no GL errors.

The docs acknowledge this behavior. That acknowledgment does not preserve the intended illustration on this capability path. The house browser rules require working art across supported browsers and machines.

**Alternatives, ranked:**

1. **Provide a portable exact-depth path.** Evaluate encoded slopes in a renderable non-float texture. Measure its rounding error against the clearance. This preserves the teaching model but needs shader work.
2. **Reject the unsupported capability explicitly.** This prevents incorrect art from appearing silently. It does not satisfy the complete browser requirement.
3. **Use larger clearances for the fallback.** This can preserve hiding, but it changes geometry and requires a second validated configuration.

Do not simply reduce the ordinary tolerance. The task’s measurements show that this removes valid outlines.

No tested engine naturally lacked the extension. These results verify the simulated capability branch, not its prevalence on other machines.

### 2. P2 — The collision guard excludes unrelated stationary meshes and misses surface intersections

**Locations:** `watch/deck.test.ts:112`, `watch/deck.test.ts:118`, `watch/deck.test.ts:120`, and `watch/at-rest.ts:70`.

The test builds `own` from every group in the disc’s piece. That piece includes the wheel and its stationary paper disc.

The disc uses the watch’s root group. Therefore, `own` includes the root group. The next filter excludes every mesh in that group.

For the fourth wheel’s disc, I measured:

- `own` contains `fourth wheel` and `watch`.
- The root group contains 25 non-holdout meshes that this filter excludes.

These meshes are not all parts of the covering wheel. The guard cannot detect their intersections.

The test also checks only vertices strictly inside the disc outline. A triangle can cross the disc without any vertex inside it. A direct probe returned zero interior points for such a triangle.

Consequently, passing this test does not establish the documented rule that no shown part rises through a shown disc.

**Alternatives, ranked:**

1. **Keep the guard, but test clipped surfaces.** Exclude only the covering wheel’s actual parts. Clip candidate triangles against the disc polygon and inspect the resulting heights.
2. **Use a conservative intersection guard.** Test projected triangle overlap and height bounds. This is simpler, but it can require explicit exceptions.
3. **Rely on saved render comparisons.** These help check appearance, but they cannot replace a geometry guard for future edits.

Also replace the exception keyed by `"centre wheel 4"` with mesh objects obtained from pieces. The numeric mesh suffix makes the exception depend on generation order.

This finding concerns test coverage. I did not reproduce an incorrect case or stud appearance in the current deck.

### 3. P3 — Round 5 compares against a reference that it does not generate

**Locations:** `tasks/2026-10-11-paper-discs/tools/render.py:71` and `tasks/2026-10-11-paper-discs/tools/render.py:184`.

Round 5 generates `clip-gap-0.02` as its baseline. Its paper variants have no explicit `reference`.

`compare()` therefore selects `clip-0.25`.

In a clean output directory, the comparison fails because that reference does not exist. I reproduced this with temporary synthetic PNGs.

If an earlier round created `clip-0.25`, the tool instead compares against that older, zero-gap geometry. The result then depends on previous runs.

**Recommendation:** Give each Round 5 paper variant `clip-gap-0.02` as its explicit reference.

An alternative is to make the first selected variant the default reference. Explicit references are clearer because other rounds use several baselines.

The task’s `pair.py` takes its reference explicitly. This defect does not, by itself, invalidate the table produced with that separate tool.

## What works well

- **The scene owns the masking geometry.** The renderer no longer knows which wheel clips another wheel.
- **Piece membership controls the discs.** Each disc shows and fades with its wheel. Holdouts retain the paper colour during dimming and flashes.
- **The case clipping has a clear purpose.** Stationary clipped discs preserve the oversized wheel’s interaction with the crown.
- **The height changes preserve meshing.** Pinions reach across the new clearance. Tests check their full height.
- **Resource ownership remains consistent.** Slope textures participate in resizing and cleanup. Sampling textures are detached from the framebuffer before line drawing.
- **The production API stays small.** Prototype switches and tuning options were removed. The task preserves them separately.
- **The exact test has a narrow scope.** Ordinary faces retain their established test. This preserves curved-wall outlines, overlays, and decals.
- **`watch/dump.ts` reflects the scene API change.** It exports the holdout flag instead of obsolete clip-disc data.

The Hour Hand slide already excludes the barrel arbor at clicks 1 and 2 on `main`. Its absence from this diff is not a missing implementation.

## Optional improvement: avoid slope buffers when a scene has no holdouts

**Location:** `webgl/renderer.ts:1002`.

Every renderer with float support allocates slope textures, even when its scene has no holdouts.

An RG32F target uses eight bytes per pixel. At 1960 × 1104, this adds approximately 16.5 MiB per target. A two-picture fade can add approximately 33 MiB.

Consider allocating these textures only when the scene contains a holdout. This would remove unnecessary storage and texture reads from other scenes.

I did not measure frame-time changes. These storage figures are calculated from the texture format, not measured GPU allocation.
