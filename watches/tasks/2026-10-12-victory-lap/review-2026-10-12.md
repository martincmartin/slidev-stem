## Findings

### 1. P2: Ending a lapse during balance resumption leaves an incorrect rest pose

**Evidence:** `watch/model.ts:895–898`, `watch/model.ts:907–920`, and `watch/model.ts:700–708`.

`endLapse()` transfers the accumulated lead only when the balance clock is free. A rest request can arrive while that clock is resuming.

The lapse then stops growing, but its fractional lead remains. `mechanismAt()` uses `swingAt()` whenever that lead is fractional. This bypasses the clock’s rest pose.

A focused model reproduction gave these results:

| Time | Reported phase | `untilRest()` | Rendered balance angle |
| ---: | --- | ---: | ---: |
| 2,000 ms | `balance rest` | 0 ms | 1.22717° |
| 5,000 ms | `balance rest` | 0 ms | 1.22717° |
| 6,000 ms | `balance rest` | 0 ms | 1.22717° |

The sequence was: place at rest; start 120× while resuming; request rest before resumption ends.

Rapid adjacent steps through the current deck also reproduce the defect. This command uses its actual frontmatter:

```bash
pnpm exec node --input-type=module <<'JS'
import { generate } from "./watch/generate.ts";
import { slideFrontmatter } from "./watch/deck.ts";
import { watchState, modelState } from "./watch/state.ts";
import { WatchModel } from "./watch/model.ts";

const watch = generate();
const model = new WatchModel(watch, 0);
const renderer = { updateMesh() {} };
const hour = await slideFrontmatter("Hour Hand");
const recap = await slideFrontmatter("Recap");
const spring = await slideFrontmatter("Mainspring");

function show(frontmatter, click, now, instantly = false) {
  const state = watchState(frontmatter, click);
  model.show(modelState(state), now, instantly);
  model.frame(now, renderer);
}

show(spring, 4, 0, true);
for (let click = 0; click <= 6; click++) {
  show(hour, click, 100 + 20 * click);
}
show(recap, 0, 240);
model.frame(340, renderer);
for (let click = 6; click >= 0; click--) {
  show(hour, click, 360 + 20 * (6 - click));
}
show(spring, 4, 500);

for (const now of [2000, 3000, 5000]) {
  const matrix = model.frame(now, renderer).get(watch.groups.balance);
  console.log({
    now,
    phase: model.phase(now),
    untilRest: model.untilRest(now),
    angle: Math.atan2(matrix[1], matrix[0]) * 180 / Math.PI,
  });
}
JS
```

At all three sampled times, this reports rest while the balance remains at approximately 0.26530°.

**Alternatives, ranked:**

1. **Handle lapse termination for every balance mode.** Start settlement from the actual mechanism pose and consume the lead once. This preserves continuity.
2. **Delay lapse activation until resumption ends.** This simplifies the contract, but changes the speed transition.
3. **Round the lead to whole periods.** This restores the rest pose, but can visibly jump the mechanism.

Add a regression for the first reproduction. The current hand-over test starts with a free clock and misses this case.

### 2. P2: The final Recap move uses different choreography when reversed

**Evidence:** `slides.md:995–1006` and `webgl/timeline.ts:485–498`.

The final stop sets `watchMove: ordered`. The preceding stop inherits `together`. The timeline selects the mode only from the destination.

A numerical probe of the actual Recap states found:

| Direction | Camera phases | Camera duration |
| --- | --- | ---: |
| Hairspring → cover | angles, then view | 3.3 s |
| Cover → hairspring | one simultaneous camera phase | 2.5 s |

In the forward move, the tilt reaches zero before the zoom changes. In the backward move, tilt and zoom change together.

This conflicts with `../docs/navigation.md:39`. That rule requires presentation moves to reverse their steps and durations. The task records the ordered forward move, but specifies no backward exception.

**Alternatives, ranked:**

1. **Resolve the move mode for the transition boundary.** Use the same mode in either direction, then reverse the ordered phases.
2. **Document a deliberate exception.** This preserves the implementation, but needs an explicit decision about backward behavior.
3. **Make both neighboring targets ordered.** This fixes this boundary but also changes the move into the Hairspring stop.

Test both directions using the deck’s actual states. Separate tests of `ordered` and `together` do not detect this mismatch.

### 3. P2: Explorer deck poses discard dimming

**Evidence:** `watch/explorer/explorer.ts:374–389` and `watch/explorer/explorer.ts:690–698`.

The pose handler obtains `stageState()`, but retains only the camera and shown meshes. The render call never supplies `stage.dim`.

The current deck has four affected positions:

| Position | Dimmed meshes |
| --- | ---: |
| Gear Train, click 5 | 45 |
| Hour Hand, clicks 3–5 | 50 each |

These poses therefore show all pieces at full strength. That defeats the documented purpose of viewing a slide “as the deck does.”

**Alternatives, ranked:**

1. **Retain and render the selected pose’s dim map.** Clear or update it when the user leaves that pose.
2. **Use a small shared settled-frame helper.** This reduces drift between explorer and stage rendering, but adds an abstraction.
3. **Limit the feature to camera previews.** This is simpler, but removes the promised pose fidelity.

The first option is sufficient for this defect. A separate explorer renderer is unnecessary.

### 4. P2: Explorer restart and saved links lose the selected motion state

**Evidence:** `watch/explorer/explorer.ts:336–345`, `watch/explorer/explorer.ts:401–403`, `watch/explorer/explorer.ts:417–425`, and `watch/explorer/explorer.ts:471–472`.

Selecting a pose gives the model its rest, spin, and Mainspring state. Restart and reload instead call `runAtSpeed()`, which always selects a free-running mechanism.

The saved address contains only the lapse speed. It cannot restore those other motion modes.

Examples from current deck states:

- Mainspring, wound: the selected pose rests the balance. Restart or reload starts it swinging.
- Mainspring, run down: restart loses the run-down spring state and stopped mechanism.
- Escapement, free-spin click: restart loses the escape wheel’s specified spin.

A focused model comparison measured 0° for the selected wound pose and approximately −150° after reconstruction as a free mechanism.

**Alternatives, ranked:**

1. **Retain a complete active motion state.** Use it for restart. Serialize that state, or a stable deck-pose reference, for reload.
2. **Clear the pose selection on restart and rename the action.** This makes the change explicit, but still limits saved links.
3. **Remove motion from the pose feature.** This reduces scope but removes useful behavior already requested.

Keep camera and visibility edits independent from the active motion state. A speed-menu change can explicitly replace that state with a free-running lapse.
