# House docs

The rules for every STEM talk: what each doc holds. When to read each one is in
[`../AGENTS.md`](../AGENTS.md), "House docs: read before you act"; keep the two
lists in step. What is true of one talk only is in that talk's `docs/` (for
`watches`: [`../watches/docs/`](../watches/docs/README.md)).

- [theme.md](theme.md): making a palette step by step, a colour value in
  Markdown, the colour roles and their washes, their gates, a slide-class
  override, adding a colour; Ledger; the house theme and its palettes
- [illustrations.md](illustrations.md): the drawing grammar (size, colour,
  stroke ladder, leaders, motion), theme colours in an SVG, washes, how to draw
  a new one
- [webgl.md](webgl.md): live 3D art: when to use it, the renderer and its
  contract, the house style in 3D, how slides drive it
- [navigation.md](navigation.md): a slide names targets, not moves: going back
  with no extra code, the default for each kind of animation, what a mouse
  click does, the check
- [legibility.md](legibility.md): the venue, the resolution and contrast floors,
  room light, how to read the metrics, text sizes
- [talks.md](talks.md): each talk as its own project: set up a clone, why,
  adding a deck file, changing a house item, validation, upgrading a talk's
  packages, publishing a talk on GitHub Pages
- [export.md](export.md): the forms of a talk for readers (the article, a
  narrated mode, a PDF): which exist, the rules, the traps
- [text-display-deep-research-report.md](text-display-deep-research-report.md):
  background, not rules: ways to show text on a screen (film, TV, games,
  explainers), the design dimensions, ranked families to prototype
- [../tools/README.md](../tools/README.md): each check, its commands, and which
  tool is the authority
